# 深技大食堂 · 深圳技术大学

一个只做**学校食堂**的网页：收录深圳技术大学五大食堂的今日菜单、菜品评分、意见反馈与消费营养统计。

> 一句话说明：面向深技大师生的**食堂信息平台**——菜单看得到、好坏评得了、意见有回应、花了多少钱和吃了多少热量记得清。

## 在线访问

**公网地址（所有人可直接打开，无需安装任何东西）：**

```
https://<用户名>.github.io/<仓库名>/
```

> 首次部署请把上面地址中的 `<用户名>` 与 `<仓库名>` 换成你自己的 GitHub 用户名和仓库名；
> 页面上「数据说明」已写明数据只存在访客本机浏览器里。

打开的页面与本地完全一致：五个食堂的菜单、评分、口碑排行全部可读可用；
每位访客的打卡、评价、反馈**只存在他自己的浏览器中**，互不干扰，也不会回传到任何服务器。

## 快速开始

**双击 `index.html` 即可**（单个 HTML 文件，零依赖、零构建、可离线）。

可选的本地静态服务：

```bash
cd /home/wyz/CodeBuddy/101
python3 -m http.server 8000 --bind 0.0.0.0
# 浏览器访问 http://localhost:8000
```

> 若在容器 / 远程环境里起服务，**必须绑 `0.0.0.0`**；只绑 `127.0.0.1` 会导致外部浏览器打不开。

首次进入填写昵称、学号（选填）并选择身份即可开始使用，无需注册密码。

## 两类用户（主路径）

| 身份 | 主路径 |
| --- | --- |
| **学生**（使用方） | 进站选「我是学生」→ 今日菜单点「🍚 我吃了这道菜」打卡 → 进菜品详情打五星并写评价 → 意见反馈里向某窗口提一条意见 → 消费与营养里看到金额与营养素随之变化 |
| **食堂管理员**（维护方） | 进站选「我是食堂管理员」→ 管理后台看到待处理反馈 → 填写内容点「受理回复」（学生端立刻可见）或「驳回」（须填理由）→ 菜品维护里改价 / 下架一道菜 → 处理记录里出现对应流水 |

任何时候点头像 →「身份管理」可切换学生 / 管理员，**切换不丢失任何数据**；管理后台入口只对管理员身份显示，非管理员访问会被拦回菜单页。

## 技术实现

- **单文件**：`index.html` 内联全部 HTML / CSS / JS / 演示数据，无任何 CDN、外部字体、外部图片，`file://` 双击离线完整可用。
- **无框架**：原生 ES6 + CSS 变量设计系统，采用「内存 db 对象 → 写操作落盘 → 全量重渲染 → 事件委托」的轻量模式。
- **渲染架构**：一个路由变量 + 六个视图（`menu` / `dish` / `rank` / `feedback` / `stats` / `admin`）；新增视图只需 `Object.assign(VIEWS, {...})` 再往 `NAVS` 加一项。
- **事件**：`document` 级委托读取 `data-act` 分发到 `ACTIONS`，每次重渲染无需重新绑定监听器，也避免了内联 `onclick` 的转义风险。
- **图片位**：全部用 CSS 渐变色块 + 菜名首字生成封面（按 id + 名称做确定性哈希取色相），彻底杜绝外部资源依赖。

## 数据说明

- 所有数据存在浏览器 `localStorage` 的 `sztu_canteen_db_v1` 键下，**不上传服务器**。
- 内置演示数据：5 个食堂、27 个窗口、76 道菜品、约 170 条同学评价、近半年的就餐打卡流水与 6 条示例反馈（含 3 条待处理，方便演示管理员受理）。
- 菜品采用软删除 `removed` 标记：下架后学生端不可见，管理员后台可一键恢复，评分会随之重算。
- 管理员的每一次受理 / 驳回 / 改价 / 上下架都会写入 `adminLogs`，后台「处理记录」可查完整时间线。
- 头像 →「身份管理」→「恢复初始数据」可清空本机数据回到初始演示状态（有二次确认）。
- 换浏览器或清除浏览数据会丢失自己发布的内容，属正常现象。
- 菜价、热量、营养值与营业时间为**演示用示例数据**，实际以食堂现场公示为准。

## 部署到 GitHub Pages

项目是**单个无依赖的 `index.html`**，没有任何构建步骤，所以用最简单的「分支直出」方式发布即可，`main` 分支根目录就是发布源。全程约三分钟。

### 1. 在 GitHub 上新建仓库

打开 <https://github.com/new>，仓库名随意（例如 `sztu-canteen`），可见性选 **Public**（Pages 需要公开仓库），
**不要**勾选 Add a README file / .gitignore / license。创建完成后复制仓库地址：

```
https://github.com/<用户名>/<仓库名>.git
```

### 2. 本地推送（在自己终端执行）

```bash
cd /home/wyz/CodeBuddy/101
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

> 首次推送会弹出 GitHub 登录授权窗口，按提示完成即可。
> 若本机已有 SSH key，也可换成 SSH 地址 `git@github.com:<用户名>/<仓库名>.git`。

### 3. 开启 Pages

进入仓库 **Settings → Pages**，在 **Build and deployment → Source** 下选择 **Deploy from a branch**，
分支选 **`main`**、目录选 **`/ (root)`**，点 Save。等待约 1 分钟即可访问：

```
https://<用户名>.github.io/<仓库名>/
```

后续只要在本地改完 `index.html` 再 `git push`，Pages 会自动在几十秒内更新。

### 部署后要注意的三件事

1. **数据是各人本地的**：公网上的页面不含任何服务器，访客的打卡、评价、反馈只写进他自己的浏览器，
   别人看不到，你也看不到；换浏览器或清缓存会丢。
2. **`file://` 与 `https://` 的本地数据互不相通**：本地双击打开累计的记录，不会同步到网页版。
3. **演示无鉴权**：任何访客都可以把身份切换为「食堂管理员」查看后台，这是本机演示的设计，
   若未来接了真实后端，务必在服务端做权限校验。

## 安全与边界

- 所有用户输入在拼接 HTML 前统一经过 `esc()` 转义，避免 XSS。
- 下架菜品、驳回反馈、恢复初始数据等破坏性操作均有二次确认。
- 本机演示不做口令校验，管理员身份仅作视角切换，无真实鉴权。
